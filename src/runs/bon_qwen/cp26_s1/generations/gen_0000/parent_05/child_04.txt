**Core Idea:**
For a fixed set of centers, the problem of finding the maximum radii such that circles do not overlap and stay within the square is a Linear Programming problem. The variables are the radii $r_i$. The constraints are linear: $r_i + r_j \le \|c_i - c_j\|$ (distance between centers) and $r_i \le \text{distance to boundary}$.

We can maximize the sum of radii $\sum r_i$ by iteratively updating the centers. The direction to move a center $c_i$ to increase the total sum of radii is given by the gradient of the LP objective function with respect to the centers. This gradient can be computed using the dual variables (shadow prices) from the LP solution.

**Algorithm:**
1.  **Initialization:** Place 26 centers in a perturbed hexagonal grid pattern inside the unit square. This provides a good starting configuration with high packing density.
2.  **Optimization Loop:**
    *   **Solve LP:** Construct the LP for the current centers. Variables: radii $r_1, \dots, r_{26}$.
        *   Objective: Maximize $\sum r_i$.
        *   Constraints:
            *   $r_i + r_j \le \|c_i - c_j\|$ for all pairs $i < j$.
            *   $r_i \le x_i$, $r_i \le 1-x_i$, $r_i \le y_i$, $r_i \le 1-y_i$ for all $i$ (boundary constraints).
            *   $r_i \ge 0$.
    *   **Extract Duals:** Retrieve the dual variables (marginals) associated with the inequality constraints.
    *   **Compute Gradient:** The gradient of the objective w.r.t center $c_k = (x_k, y_k)$ is derived from the dual variables:
        *   Pairwise constraints ($r_i + r_j \le d_{ij}$): If dual $\lambda_{ij} > 0$, moving $c_k$ away from $c_j$ increases $d_{ij}$, potentially increasing radii. Contribution: $\lambda_{ij} \frac{c_k - c_j}{d_{ij}}$.
        *   Boundary constraints ($r_i \le b_i$): If dual $\mu > 0$, moving $c_k$ away from the boundary increases the allowed radius. E.g., for $r_i \le x_i$, gradient is $+\mu$ in $x$ direction.
    *   **Update Centers:** Move centers in the direction of the gradient (ascent) with a small step size. Clip centers to $[0, 1]$.
    *   **Repeat:** Iterate for a fixed number of steps or until convergence.
3.  **Final Polish:** After the iterative process, solve the LP one last time to get the optimal radii for the final centers.

**Implementation Details:**
*   Use `scipy.optimize.linprog` to solve the LP.
*   Use sparse matrices for efficiency if needed, though for $N=26$ dense is fine.
*   Handle numerical stability (e.g., division by zero if centers coincide).
*   The gradient update is essentially a force-directed layout where "forces" are determined by how much relaxing a constraint (increasing distance) improves the objective.

This method decouples the complex non-linear geometry into a sequence of linear problems and gradient steps, which is robust and efficient for this scale.
